# 3目並べで学ぶ強化学習の基礎 — ランダムプレイからQ学習まで

本リポジトリは，3目並べ(Tic-Tac-Toe)を題材として，ランダムプレイ・方策反復法・価値反復法・
モンテカルロ法・Q学習という順序で強化学習の基礎を段階的に学ぶための教材である．
3目並べの環境をNumPyのみでフルスクラッチ実装し，動的計画法(方策反復法・価値反復法)，
モンテカルロ法，Temporal Difference学習(Q学習)の違いを実験的に比較・可視化する．
評価・対戦機能まで実装することが最終到達点である．

全てのノートブックはGoogle Colab上での実行を前提としている．
各実験の冒頭にある「Open in Colab」バッジから直接開ける．

## 1. リポジトリの思想

1. **骨格固定・差分最小**: 全実験で共通の学習・評価ループの構造(`TicTacToeEnv`, `BaseAgent`,
   `evaluate`, `play_human_vs_ai`, `ResultLogger`, `set_seed`等)を用いる．
   実験ごとに変えるのは，エージェントの価値更新アルゴリズムのみである．
   サードパーティ製ライブラリはNumPyとMatplotlibのみに限定し，強化学習ライブラリ(Gym等)は
   使用せずフルスクラッチで実装する．
2. **1ファイル=1実験・自己完結**: 各実験は1つのGoogle Colab対応ノートブック(`exNNN_*.ipynb`)に
   閉じ，他の実験ファイルをimportしない．共通処理はコピー＆微修正とし，DRY(重複の排除)よりも
   「実験間の差分の可視性」を優先する．実験間でのデータの受け渡しは，コードのimportではなく，
   `outputs/`に保存された学習結果(Q値テーブル等)の読み込みのみによって行う(ex003・ex006で使用)．
3. **理論とプログラムの分離**: 各`exNNN_*.ipynb`にはプログラムの実装のみを記載する．
   目的・数式・実験条件・考察・発展課題といった理論的な解説は，対応する`exNNN_*.md`にまとめる．
   状態価値関数 $`V(s)`$ や行動価値関数 $`Q(s,a)`$ の更新式を数式で明記し，コード中のどの変数・
   どの行がその数式のどの項に対応するかを`.md`側で説明する．
4. **問い→予想→実験→結果→考察→発展のサイクル**: 各`exNNN_*.md`は，実験前に予想する問いを立てる．
   結果・考察・発展課題の回答例は折りたたみ(`<details>`)にし，学習者が自分で予想・考察を
   書いてから開ける構成にしている．

### 環境のMDP化に関する設計判断

3目並べは2人零和ゲームであるが，方策反復法・価値反復法(動的計画法)は「既知の遷移確率」を
要求する．そこで本教材では，学習エージェントは常に先手(X)とする．
後手(O)は，合法手から一様ランダムに1手を選択する固定方策に従う「環境の一部」とみなす．

この定式化のもとでは，遷移確率 $`p(s'\mid s,a)`$ がゲーム規則から解析的に計算できる．
これは1エージェント視点のマルコフ決定過程(MDP)であり，動的計画法(ex002・ex003，環境モデル既知)
とモデルフリー手法(ex004・ex005，同じ相手方策からのサンプリングのみで学習)を公平に比較できる．

ex006では，この前提(学習済みエージェントは先手専用である)を踏まえる．
「先手が一様ランダムに打つ場合に最適に打つ後手」を新たに構築し，これを共通の評価基準として
全手法を比較する．

## 3. 使い方

強化学習が初めての場合は，まず[ex001_random_baseline.md](ex001_random_baseline.md)の
「0. 強化学習の基礎用語」を読み，状態・行動・報酬・方策などの用語を確認することを推奨する．

1. `ex001`から順に，`.ipynb`の「Open in Colab」バッジからノートブックを開いて実行する．
2. 実行前に，対応する`.md`を読み，「目的」「手法」「実験条件」を確認する．
   「実験前に考える」の問いに対して，自分の予想を書く．
3. ノートブックを実行し，結果(学習曲線・評価値・保存された図)を得る．
   `.md`の「実験結果」「実験後に考える」「考察」の折りたたみを開いて答え合わせをする．
4. `ex001`〜`ex005`を実行すると`outputs/`に学習結果が蓄積される．
   `ex006`ではそれらを読み込んで5手法を横断的に比較する．
   全実験の実行後は，[visualize_result.ipynb](visualize_result.ipynb)でも
   `outputs/`配下の結果を横断的に可視化できる．
5. 学習済みエージェントと対人対戦したい場合は，`ex006_comparison_and_play.ipynb`末尾の
   `RUN_INTERACTIVE`を`True`に変更して実行する．
   自動実行時に入力待ちで停止しないよう，既定はFalseとしている．

## 4. 共通ハイパーパラメータ

| パラメータ | 値 |
| :--- | :--- |
| 割引率 $`\gamma`$ | 0.95 |
| DP収束判定閾値 $`\theta`$ | 1e-4 |
| 探索率 $`\epsilon`$(MC・Q学習) | 0.1 |
| 学習率 $`\alpha`$(Q学習) | 0.1 |
| 学習エピソード数(MC・Q学習) | 10,000 |
| 評価エピソード数 | 1,000 |
| シード数 | 3(0, 1, 2) |

**根拠**:

- $`\gamma`$: 3目並べは有限ステップの終端ゲームであり $`\gamma=1.0`$ でも収束するが，手数による価値の減衰を可視化しやすくするため段階的な値を採用した．
- $`\theta`$: 状態数が2,423(Xの手番かつ非終端)と少なく，十分小さい閾値でも現実的な反復回数(5〜15スイープ)で収束する．
- $`\epsilon`$: 固定相手(ランダム)に対する探索と活用の標準的なバランス．
- $`\alpha`$: テーブル型TD学習における標準的な初期値．
- 学習エピソード数: 対ランダム方策の勝率がエピソード数を増やしてもほとんど改善しなくなる(50,000エピソードとの差が1パーセント程度に収まる)点を予備実験で確認した上で，学習時間を抑えるために10,000エピソードとした．
- 評価エピソード数: 勝率推定の分散を抑えるため．
- シード数: 学習曲線の平均・標準偏差を`visualize_result.ipynb`で可視化するため．

## 5. 共通クラス・関数の役割

| 名前 | 役割 |
| :--- | :--- |
| `set_seed(seed)` | 乱数シードを固定する |
| `ResultLogger` | 学習曲線をJSONに保存・読込する |
| `TicTacToeEnv` | 3目並べの環境クラス |
| `BaseAgent` | 全エージェントの基底クラス |
| `RandomAgent` | ランダム方策のエージェント |
| `TabularQAgent` | Q値テーブルに基づく貪欲方策のエージェント |
| `HumanAgent` | 人間が操作するエージェント |
| `evaluate(...)` | 2エージェントを対戦させ成績を測る |
| `play_human_vs_ai(agent)` | 対人対戦の対話的インタフェース |

補足:

- `TicTacToeEnv`は`reset`, `step`, `get_valid_actions`, `render`に加え，動的計画法用に`transition_model`(既知の環境モデル)と`enumerate_states`(到達可能状態の列挙)を持つ．
- `TabularQAgent`が扱うQ値テーブルはNumPy配列(形状`(3**9, 9)`)であり，動的計画法・モンテカルロ法・Q学習いずれの最終方策もこの形式に統一している．
- `evaluate(agent, opponent, n_episodes, seed)`は，任意の2エージェントを対戦させ，勝率・引き分け率・敗率を返す．

## 6. 結果の保存規則

学習結果は以下の規則で`outputs/`配下に保存する．
同一条件の結果が既に存在する場合は，再学習をスキップする．

```text
outputs/{実験名}/{アルゴリズム名}/{ハイパーパラメータ}/{seed}/
    ├── Q.npy          # 学習後の行動価値テーブル Q(s,a), 形状(3**9, 9)
    ├── log.json        # ResultLoggerによる学習曲線(訓練時の指標)
    ├── eval.json        # evaluate関数による最終評価(勝率・引き分け率・敗率)
    └── config.json      # そのランの全ハイパーパラメータ・学習時間等のメタデータ
```

`log.json`(訓練時の指標)には，一定間隔ごとに現在の貪欲方策を少数エピソード(300)で
簡易評価した値を記録する．
`eval.json`(最終評価)には，学習終了後の方策を1,000エピソードという
より多くのエピソードで評価した値を記録する．

`ex006_comparison_and_play.ipynb`の比較結果は`outputs/ex006_tictactoe_comparison/`に，
`visualize_result.ipynb`による横断比較結果は`outputs/_comparison/`に保存する．

`outputs/`はGit管理下にあり，`Q.npy`もリポジトリに含まれる．
Google Colabでノートブックを単体で開いた場合，そのインスタンス上には他の実験の結果が
存在しない．`ex003`・`ex005`・`ex006`は，このような場合に本リポジトリを自動でクローンして
`outputs/`を参照する．`ex006`の対人対戦セルでは，対戦相手のQ値テーブルのパス(`Q_PATH`)を
自由に書き換えられるようにしており，任意の`.npy`ファイル(別の条件で学習した結果や，
自分でアップロードしたファイル)を対戦相手として使用できる．
