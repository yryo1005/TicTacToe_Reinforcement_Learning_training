# リポジトリの思想（すべての実験で厳守）

1. 【骨格固定・差分最小】
全実験で共通の学習/評価ループ構造と共通のクラス・関数名を使う。
実験ごとに変えてよいのは「エージェントの価値更新アルゴリズム（モデル定義・損失/更新式）」の点のみに限定する。
サードパーティ製ライブラリは NumPy および Matplotlib のみに限定し, 強化学習ライブラリ（Gym等）は使用せずフルスクラッチで実装する。
共通クラス・関数の例:
* set_seed: 乱数固定
* TicTacToeEnv: 3目並べの環境クラス（reset, step, get_valid_actions, render 等）
* BaseAgent: エージェントの基底クラス（select_action, update 等）
* evaluate: ランダムエージェントや過去モデルとの対戦による勝率・引き分け率の評価ループ
* play_human_vs_ai: 人間対AIの対戦用UI機能
* ResultLogger: 学習曲線（収束速度, 勝率推移）を log.json や 描画用データとして保存するクラス


2. 【1ファイル=1実験、自己完結】
各実験は1つのGoogle Colab向けノートブック（または1つのスクリプト）に閉じ, 他の実験ファイルをimportしない。
共通処理はコピー&微修正でよい（DRYより「差分の可視性」を優先する）。
3. 【数式とコードの対応】
各実験の解説ファイルには, 状態価値関数 $V(s)$ や行動価値関数 $Q(s, a)$ の更新式を数式で明記し, コード中のどの変数・どの行がその数式のどの項に対応するかを説明する。
4. 【問い→予想→実験→結果→考察→発展のサイクル】
各実験の解説ファイルは次の構成にする（詳細は下記テンプレート参照）。
結果・考察・発展課題の回答例は折りたたみ（タグ等）にし, 学習者が自分で予想・考察を書いてから開く設計にする。

# 実験系列の設計方針

3目並べを通じたQ学習以前からQ学習までの基礎強化学習（ランダムプレイ, 方策反復法, 価値反復法, モンテカルロ法, Q学習） に到達するまでの実験を, 単純なベースラインから始めて1回の変更で1つの新しい概念だけを追加する形で段階的に並べること。
各段階で「前の実験との差分は何か」を1〜2文で言えるようにする。

* 段階1（ex001）: 3目並べ環境のフルスクラッチ実装とランダムプレイによる動作検証および評価基盤の構築
* 段階2（ex002）: 完全な環境モデル（遷移確率・報酬）を用いた動的計画法1：方策反復法（Policy Iteration）の実装
* 段階3（ex003）: 完全な環境モデルを用いた動的計画法2：価値反復法（Value Iteration）の実装と方策反復法との収束性比較
* 段階4（ex004）: 環境モデル不完全/未知を想定したモデルフリー学習1：モンテカルロ法（Monte Carlo Control）の実装
* 段階5（ex005）: TD学習（Temporal Difference Learning）によるモデルフリーオフ方策学習：Q学習（Q-Learning）の実装
* 段階6（ex006）: 各手法の学習効率・対戦強度の総合比較可視化および対戦機能（Human vs AI）の実装

各段階は「実験番号・実験名・モデル・主な損失・前実験との主な差分」を1行にまとめた一覧表をREADMEに作ること。

# 生成してほしいファイル構成

* README.md : リポジトリ全体の説明（思想, ファイル構成, 実験系列の一覧表, 共通ハイパーパラメータ表, 共通関数の役割表, 結果保存規則, 使い方の手順）
* exNNN_{{短い実験名}}.{ipynb|py} : 各実験の実装（自己完結, Google Colab対応）
* exNNN_{{短い実験名}}.md : 各実験の解説（構成は下記テンプレート参照）
* figures/ : 学習曲線・勝率変化・対戦可視化画像の格納先

# 各実験の解説ファイル（exNNN_*.md）の構成テンプレート

1. 目的
* 本実験で何を確認したいか。講座全体のどの段階に位置するかを1〜2段落で述べる。


2. 手法
2.1 環境・エージェント定義: 状態表現, 行動空間, 遷移モデルを数式で記述
2.2 目的関数・更新式: 最小化/最大化する価値関数・ベルマン方程式を明示し, 記号の意味を定義
2.3 評価指標: 勝率, 負け率, 引き分け率, 価値関数の収束度（$\max_s \vert{}V_{k+1}(s) - V_k(s)\vert{}$ 等）を数式で定義
3. 実験条件（表）: 割引率 $\gamma$, 探索率 $\epsilon$, 学習率 $\alpha$, 収束判定閾値 $\theta$, エピソード数, シード, 結果の保存先パス
* 「実験前に考える」: 実験を実行する前に答えさせる問いを2〜4個。結果を予想させ, 根拠を書かせる。答えは直後に書かない。


4. 実験結果（折りたたみ、先に予想してから開く）
* 学習曲線・指標の表・可視化画像（勝率推移や価値観数のヒートマップ等）
* 「実験後に考える」: 予想と実際の結果を照合させる問い。単なる感想ではなく, 理論的な問い（なぜ動的計画法とモデルフリーで収束速度やデータ効率に差が出るか等）にする。


5. 考察（折りたたみ）
* 結果が理論的に何を意味するか。次の段階の実験にどうつながるかを述べる。


6. まとめ: 3〜5行の箇条書き
7. 発展課題
* 何を変更するか（具体的なコード差分レベルで指示）
* 何を比較するか
* 予想
* 回答例（折りたたみ）: 実装例, 期待される結果, 結果から分かること



# 共通ハイパーパラメータ・実行環境の記載

README.md に, 全実験で共通する設定（データセット/環境ルール, 割引率 $\gamma$, 最適化閾値 $\theta$, 評価エピソード数, シード, 実験固有のハイパーパラメータとその設定根拠）を表でまとめること。設定根拠が経験的に重要な場合（例: 3目並べは有限段階ターミナルゲームであるため割引率 $\gamma=1.0$ でも収束するが, 段階的評価のために $\gamma=0.9~0.99$ を選択する理由等）は一言添える。

# 結果の保存規則

学習結果は `outputs/{実験名}/{アルゴリズム名}/{gamma}_{alpha}_{epsilon}/{seed}/` のような一貫した規則で保存し, 同一条件の結果が既にある場合は再学習をスキップする設計にすること。
